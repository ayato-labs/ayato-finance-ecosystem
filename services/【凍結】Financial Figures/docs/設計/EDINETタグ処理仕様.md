# EDINET タグ処理パイプライン詳細仕様

本書では、日本市場の法定開示情報（EDINET）から財務データを抽出し、標準化された形式へ変換するパイプラインの技術仕様について解説します。

## 1. 処理フローの全体像

EDINETデータの処理は、以下の4つのステージで構成されています。

1. **マスター同期**: 証券コードとEDINETコードの紐付け。
2. **生データ抽出**: XBRL/CSVファイルからの要素抽出。
3. **AIマッピング**: 抽出されたタグの標準ラベルへのマッピング。
4. **正規化と永続化**: 標準スキーマへの変換とデータベース保存。

---

## 2. 各ステージの詳細

### 2.1 マスター同期 (`src/edinet/mapping.py`)
金融庁が提供する `EdinetcodeDlInfo.csv` を解析し、証券コード（4桁）とEDINETコード（EXXXXX）の対応表を構築します。
- **正規化**: 5桁の証券コード（チェックディジット付き）を4桁に変換。
- **フィルタリング**: 上場企業のみを対象として抽出。

### 2.2 生データ抽出 (`src/edinet/parser.py`)
EDINETの書類（主に有価証券報告書、四半期報告書）に含まれるCSV（Type 5）を解析します。
- **動的カラム検出**: 「要素ID」「項目名」「コンテキストID」「値」などのカラムを動的に特定。
- **数値クリーニング**: 全角スペースの除去、カンマの削除、負数表記（括弧書き）のマイナス変換。
- **抽出項目**: Element ID (例: `jppfs_cor:NetSales`), Element Name, Unit, Value.

### 2.3 AIマッピング (`src/edinet/mapper.py`)
抽出された生タグ（Element ID）を、J-Quants V2 準拠の標準ラベルへマッピングします。
- **AIエンジン**: Google Gemma-4 モデルを使用。
- **入力データ**: `(要素ID, 項目名)` のペアをコンテキストとして提供。
- **マッピング先**: `NetSales`, `OperatingProfit`, `Profit` などの標準指標。
- **トレーサビリティ**: AIによるマッピング理由はすべて監査データベース (`traceability.duckdb`) に記録。

### 2.4 正規化 (`src/edinet/mapper.py` 内 `normalize_facts`)
マッピングされた結果を基に、以下の統一フォーマットに変換します。
- 証券コード、開示日、会計年度、四半期。
- 抽出された数値と単位。
- 提出書類の受理番号（Accession Number）。
- セッションID（同期の追跡用）。

---

## 3. データベース構造 (`edinet.duckdb`)

抽出されたデータは `edinet` シャードの以下のテーブルに保存されます。

- **`documents`**: 書類メタデータ（提出日、提出者名など）。
- **`raw_facts`**: 抽出された全ての生データ（マッピング前）。
- **`company_facts`**: AIによって標準ラベルが付与された正規化データ。

---

## 4. 特筆すべきロジック

### コンテキストの活用
EDINETのデータは「連結/単体」「当期/前期」などのコンテキスト情報を持ちます。パーサーはこれらを `context_id` として保持し、正規化時に適切な会計期間へ割り当てます。

### AIマッピングの信頼性
単なる文字列一致ではなく、要素ID（タクソノミ構造）と項目名の両方をAIに提供することで、日本特有の勘定科目名称の揺れを吸収し、高い精度でマッピングを実現しています。
