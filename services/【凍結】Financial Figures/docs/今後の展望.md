# 今後の展望 - Financial Figures テストスイートの高度化

本プロジェクトでは、`Financial Figures` パイプラインの信頼性を担保するため、単体テストの再構築およびカオステスト（異常系テスト）の実装を完了しました。今後は、より実運用に近い環境での検証を強化するため、以下の項目に取り組む予定です。

## 1. テストレイヤーの拡張

### 結合テスト (Integration Tests)
- **外部API連携の検証**: EDINET APIからのデータ取得とストレージへの保存が、モックなしで（またはサンドボックス環境で）正しく連動するかを検証します。
- **マスター・シャード間同期**: `MasterManager` を介した複数シャードの作成・切り替え・状態管理が、一貫性を保って動作することを検証します。

### 総合テスト (System / E2E Tests)
- **エンドツーエンド・ユーザーフロー**: データ取り込み（Ingestion）から、解析（Parsing）、構造化保存（Storage）、そして分析用データ出力までの全工程が、実際の運用フロー通りに完結することを検証します。
- **回復シナリオの検証**: 処理途中でプロセスがクラッシュした際、`job_tracker` の状態から正しくレジューム（再開）できるかを確認します。

## 2. 運用・自動化の強化

### CI/CD パイプラインへの統合
- GitHub Actions を活用し、プルリクエスト作成時に今回構築したテストスイートが自動実行される仕組みを構築します。
- カオステスト（DB破損シミュレーション等）を含めることで、破壊的な変更に対する早期警戒網を形成します。

### パフォーマンス・負荷テスト
- 数千件規模のドキュメントを同時に処理した際の DuckDB のパフォーマンスと、ファイルロック競合の発生率を計測し、最適化を行います。

## 3. データ整合性の深化

### スキーマ進化テスト
- 将来的なスキーマ変更（マイグレーション）において、既存データが破損せず、正しく移行されることを検証する自動テストを追加します。
- `MigrationManager` のバージョン管理ロジック自体の堅牢性を高めます。

## 4. セキュリティテストの継続
- SQLインジェクション攻撃への耐性テストに加え、ファイルパス操作（Path Traversal）や入力データのオーバーフロー等、より広範な攻撃ベクターに対する防御策を継続的に強化します。
