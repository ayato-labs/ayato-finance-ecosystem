# RAM使用効率の向上のための実施事項

本プロジェクトでは、大量の財務データ（EDGAR）を効率的に処理するため、DuckDBの特性を最大限に活かしつつ、リソース消費を最適化する以下の工夫を導入しています。

## 1. 動的なリソース割り当て (Dynamic Resource Scaling)
実行環境のスペックに合わせて、DuckDBが使用するメモリ上限とスレッド数を自動的に調整します。
- **メモリ上限の自動計算**: `psutil` を使用してシステム全体の物理メモリを取得し、その**70%**を上限として動的に割り当てます。これにより、OSや他のプロセスを圧迫することなく、利用可能なリソースを最大限に活用します。
- **CPUスレッドの最適化**: `os.cpu_count()` に基づき、ハードウェアのコア数に合わせたスレッド数を設定し、並列処理効率とメモリ消費のバランスを維持します。

## 2. 定期的なメモリフラッシュ (Periodic Checkpoints)
大量データのインジェスト中、メモリ上に溜まったデータを強制的にディスクへ書き出し、メモリを解放します。
- **バッチごとのチェックポイント**: バルク挿入において、5万件のレコードを保存するたびに `CHECKPOINT;` を実行します。これにより、DuckDBのバッファマネージャが保持しているメモリが解放され、処理の進行に伴うメモリ消費の累積（OOMの主な原因）を防止します。

## 3. インデックス管理の最適化
インデックスの作成は非常にメモリを消費する作業であるため、以下の戦略をとっています。
- **一括挿入中のインデックス削除**: 大量データの挿入（Bulk Ingest）の開始前にセカンダリインデックスを削除し、挿入完了後に再構築します。これにより、挿入時のインデックス更新コストとメモリ消費を回避します。
- **再構築直前のフラッシュ**: インデックスを再構築する直前に再度 `CHECKPOINT;` を実行し、インデックス作成に必要なソート処理などのために最大限のメモリ空き容量を確保します。

## 4. 挿入順序保持の無効化 (Preserve Insertion Order = False)
バルクデータロードにおいて、DuckDBのデフォルト設定である「挿入順序の維持」を無効化しています。
- **メモリ節約**: 挿入順序を保証するための内部状態を保持する必要がなくなるため、メモリ消費量とテンポラリファイルの生成を大幅に削減できます。

## 5. 明示的なガベージコレクション (Explicit Garbage Collection)
Pythonのメモリ管理を補助するため、メモリ消費が激しい処理の直後に `gc.collect()` を実行しています。
- **実装箇所**: バルクインジェストの各バッチ処理後、およびデータの保存（`_save_optimized`）の直後。
- **効果**: Pandas DataFrameや一時的なJSONパース用オブジェクトなど、参照が外れた巨大なオブジェクトを即座に破棄し、OSへメモリを返却します。

## 6. 専用一時ディレクトリの設定 (Dedicated Temp Directory)
DuckDBがメモリ上限に達した際に使用する一時的な書き出し（Spilling）領域を最適化しています。
- **設定**: システム標準のTemp領域ではなく、プロジェクトのデータディレクトリ内の `temp` フォルダを明示的に指定。
- **効果**: OS側のTemp管理制限や断片化による影響を排除し、メモリからディスクへのデータ退避を安定化・高速化させます。

## 7. 数値データ型の選択方針 (Float64 vs Float32)
RAM効率向上のため `float32`（単精度）への変換を検討しましたが、最終的に **`float64`（倍精度 / DuckDBのDOUBLE）を維持** する決定をしました。
- **不採用の理由**: `float32` の有効桁数は約7桁であり、数兆ドル規模の財務数値や億単位の株式数を正確に保持するには不十分であるため（丸め誤差のリスク）。
- **結論**: 財務データの正確性を優先し、型を落とすのではなく、上記1〜6の「処理構造の改善」によってRAM効率を高める方針を採用しました。

## 8. スロットリングとバッチ制御
Pythonプロセス側でのメモリ消費を抑えるため、以下の制御を行っています。
- **ストリーム処理**: ZIPアーカイブ内のファイルを1つずつ展開・処理し、一度にすべてのデータをメモリに載せないように設計。
- **適切なサブバッチサイズ**: 内部的なDataFrameの処理サイズを調整し、メモリスパイクを抑制。
