# 概念的要件定義書 - edgar_provider

## 1. 背景と目的
`edgar_provider` は、米国証券取引委員会（SEC）の EDGAR システムから取得した財務データおよび定性情報（テキストデータ）を、エコシステム内の他のサービス（分析エンジンやレポートジェネレータなど）に安定して供給するためのデータプロバイダーサービスです。

本ドキュメントは、機能の追加や設計の決定において、「何をどのような方針で実装し、何をどのような方針で実装しないのか」という根本的な境界線を定義します。

---

## 2. 実装する事項とその方針

### 2.1. データの「完全性」を維持した取得と保存
- **内容**: SEC から取得した財務数値（Facts）およびテキスト（Narratives）を、意味的に一切の損失（Lossless）なく保存します。
- **方針**: 分析や監査において、元の提出書類と齟齬がないことを保証するため。テキストの要約やセンチメント分析は後続のサービスに委ね、本サービスでは生データ（または忠実なマークダウン）の保持に徹します。

### 2.2. 枯れた技術による「ストレージ効率」の最大化
- **内容**: DuckDB を主データベースとし、テキストデータには「辞書付き Zstd 圧縮」を適用します。
- **方針**: 財務報告書には膨大な定型文が含まれるという特性を活かし、計算コスト（CPU）とストレージコストのバランスが最も優れた、実績のある技術（DuckDB, Zstd）を採用して副作用のない効率化を図るため。

### 2.3. 「疎結合」なアーキテクチャ
- **内容**: データの取得（Ingestor）と、APIによる提供（Provider）の関心を分離します。
- **方針**: SEC API のレート制限（10 requests/sec）や、ファイリングの更新頻度（バッチ的）に対応しつつ、API サーバの応答性を独立して担保するため。

### 2.4. パイプラインの非同期・キューによる疎結合化
- **内容**: `非同期外部API（並列） -> キュー -> 非同期解析（並列） -> キュー -> 直列での非同期DB書き込み` というパイプラインを構築します。
- **方針**: SEC API のレート制限（10 req/sec）をフルに活用して最速でダウンロードし、CPU負荷の高い解析を並列化しつつ、DuckDBの書き込みロックを避けるために保存は直列化するため。

### 2.5. 「マニフェスト・フィルタリング」の徹底
- **内容**: データのダウンロード前に必ずマニフェスト（インデックスや提出一覧）を取得し、必要なデータのみをフィルタリングしてダウンロードします。
- **方針**: 不要な通信を排除し、SEC API のレート制限を無駄に消費しないため。

---

## 3. 実装しない事項とその方針

### 3.1. 高度な分析、可視化、およびビジネスロジック
- **内容**: 財務指標の予測、センチメントスコアリング、Web UI などの実装は行いません。
- **方針**: 単一責任の原則（Single Responsibility Principle）を維持するため。本サービスは「データの正確な供給」にのみ責任を持ち、分析や可視化は上位のアプリケーション（例: `Financial Narratives` など）の責務とします。

### 3.2. リアルタイムのデータ監視およびストリーミング
- **内容**: SEC のファイリングを秒単位で監視したり、WebSocket 等でストリーミング配信する機能は実装しません。
- **方針**: SEC のデータは定期的なバッチ（日次や四半期）で確定するものであり、リアルタイム性は求められないため。過度なポーリングは SEC API の制限に抵触するリスクを高めるだけであり、定期バッチによる確実な同期を優先します。

### 3.3. 独自の難解な圧縮・暗号化アルゴリズム
- **内容**: 独自の圧縮方式や、複雑な暗号化レイヤーは導入しません。
- **方針**: 将来のメンテナンス性とデータの可読性を最優先するため。標準的なライブラリ（Pythonの `zstandard` や DuckDB のネイティブ機能）で解決できる範囲に留め、ブラックボックスを作らないようにします。

---

## 4. 技術選定の基本方針
- **「迷ったら枯れた技術」**: 新規性よりも、実績と安定性を重視します。
- **「データの非破壊」**: ストレージ容量のために、データの情報量を削る（不可逆圧縮やサマリー化）ことはしません。
- **「外部依存の最小化」**: 可能な限り標準ライブラリや広く普及したOSS（DuckDB, Loguru 等）で完結させ、システム全体の複雑性を抑えます。
