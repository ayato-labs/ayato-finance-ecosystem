# ADR-0011: 直接ドキュメントURL解像による二重通信の撤廃および非同期並列ダウンロードの導入

## ステータス

承認済み

## 概要

SEC EDGAR からの開示書類（10-K, 10-Q）収集パイプラインのスループットを大幅に向上させるため、以下の2大最適化を実施する：
1. **二重通信の全廃 (Direct URL Resolution)**: SEC Daily Index (`master.idx`) のファイルパス文字列から直接一次ドキュメント名（`primaryDocument`）および取得URLを即座に解像し、書類ごとに行っていた事前のメタデータエンドポイント（`CIKxxxxx.json`）呼び出しを全廃する。
2. **非同期並列ダウンロードの導入 (Parallel Fetching with Semaphore)**: SEC利用規約（1秒間10リクエスト以下）を遵守する同時並行セマフォ制御 (`asyncio.Semaphore(8)`) を組み込み、非同期並列ダウンロードバッチによりスループットを従来の 3〜4 倍へ引き上げる。

## 背景

これまでの `sync_recent_us_filings` では、`master.idx` から書類リストを取得したのち、ダウンロード直前に各書類ごとに `fetcher.resolve_filing_metadata()` を呼び出し、SECの `submissions/CIKxxxxx.json` エンドポイントへ個別に問い合わせを行っていた。

この設計には以下の課題が存在した：
1. **二重のHTTP通信オーバーヘッド**: Daily Index ですでに書類の存在が分かっているにもかかわらず、毎回個別にAPIエンドポイントへ問い合わせが発生し、1秒あたり10リクエストの制限と相まって大幅な待ち時間が発生していた。
2. **直列ダウンロードによる速度ボトルネック**: ダウンロード処理が 1 件ずつ直列で実行されており、ネットワーク帯域とCPUリソースが十分に活かされていなかった。

## 決定事項

1. **`master.idx` の `filename` から直接メタデータ解像**
   - インデックスファイル行の `parts[4]`（例: `edgar/data/320193/0000320193-25-000001/aapl-20250927.htm`）から、`primaryDocument` (`aapl-20250927.htm`) をパース処理で直接抽出する。
   - 個別の `resolve_filing_metadata()` 通信を完全スキップし、通信回数を 0 回にする。
2. **`asyncio.Semaphore(8)` による安全な並列ダウンロード**
   - SEC Rate Limit（秒間10リクエスト）を超えないよう、最大 8 並列に制御されたセマフォプールでダウンロードとセクション抽出を実行する。

## 利点

1. **処理速度の飛躍的向上**: 不要な事前通信の全廃と並列処理により、同期パイプライン全体の所要時間を 70〜80% 削減する。
2. **SEC規約の完全遵守**: セマフォと適切なウェイト制御により、429エラーを発生させずに安定したハイスループットを実現する。
