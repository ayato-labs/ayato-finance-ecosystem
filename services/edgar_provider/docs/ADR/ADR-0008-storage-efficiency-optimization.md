# ADR-0008: ストレージ使用効率の最適化と自動マイグレーション

## ステータス

承認済み

## 概要

DuckDBを用いたEDGARデータのストレージ使用効率を飛躍的に向上させるため、列指向エンコーディング（Dictionary Encoding）、不要領域の自動開放（CHECKPOINT / VACUUM）、および既存データベースの自動スキーママイグレーション機構を導入する。

## 背景

SEC EDGARからパースした大量の財務数値（Facts）および定性テキスト（Markdown）をDuckDBに蓄積していく過程で、以下の課題が生じていた：

1. **重複文字列による容量圧迫**: `company_facts` テーブルの `concept`（例: `us-gaap/Revenues`）や `unit`（例: `USD`）等の繰り返し文字列が可変長文字列（`VARCHAR`）としてそのまま保持され、ストレージを浪費していた。
2. **空き領域（Unused Pages）の滞留**: 大量の `INSERT OR REPLACE`（UPSERT）操作に伴い、旧バージョンのブロックやWALがディスク上に無駄に残留していた。
3. **既存DBとの互換性とスムーズな移行**: スキーマ最適化やインデックス変更を行った際、過去に構築された `edgar.duckdb` が存在する環境でも破壊やエラーを起こさず、自動的に最新の最適化スキーマへ安全にマイグレーションする仕組みが必要であった。

## 決定事項

1. **辞書エンコーディング (Dictionary Encoding) の適用**
   - 繰り返し発生する `concept`, `unit`, `fiscal_period`, `form`, `ticker` などのカラムに対し、DuckDBの列圧縮（辞書エンコーディング）の設計原則を適用する。
2. **自動メンテナンス機能（CHECKPOINT / VACUUM）の実装**
   - DB初期化・クローズ・大規模バッチ処理完了時に `CHECKPOINT` を自律発行し、WALや不要ページを解放する。
3. **既存DBのシームレス自動マイグレーション機能 (`migrate_db`)**
   - 接続時に既存DBのテーブル構造やカラム存在・型を自動検知。
   - 不足カラムの追加（`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）や、再構成が必要な場合はデータ整合性を保ちながら新スキーマへ透過的にマイグレーションを実行する。

## 利点

1. **ストレージ容量の削減**: 繰り返し文字列の圧縮と定期的なVACUUM/CHECKPOINTにより、ディスク使用量を大幅に削減（定量データ部で最大 40〜60% の削減を見込む）。
2. **クエリパフォーマンスの向上**: ディスクI/Oが削減され、特に `concept` や `period_end` での集計・フィルター処理が高速化する。
3. **安全な運用**: ユーザーが手動でデータベースを削除・再構築することなく、コードのバージョンアップに伴い自動で既存データが最適化スキーマへ移行される。

## 専門家レビュー意見の反映

- **データベースエンジニア**: DuckDBにおける `CHECKPOINT` および列指向での繰り返し文字列管理は物理I/O削減に非常に効果的。
- **SRE / インフラ**: 既存DBからの自動マイグレーション（後方互換性維持）により、ダウンタイムや運用負荷ゼロでのアップデートを実現。
