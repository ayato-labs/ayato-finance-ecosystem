# XBRLタグ抽出ロジック解説

本ドキュメントでは、EDINET（日本市場）の iXBRL/HTML ファイルから定性情報（ナラティブ）を抽出する最新のロジックについて解説します。

## 1. 基本方針：タグ・アグノスティック抽出

従来の XBRL パーサーでは、特定の項目名（例：`ResearchAndDevelopmentActivitiesTextBlock`）をハードコードして抽出していましたが、日本の EDINET 体系は名前空間やタグの命名が非常に複雑で頻繁に変化するため、以下の「タグ・アグノスティック（タグ非依存）」な方針を採用しています。

- **全量捕捉 (Greedy Extraction)**: 特定のタグを選別せず、`ix:nonNumeric` タグで囲まれたすべてのセクションを抽出します。
- **名前空間の維持**: 抽出時のキーには名前空間（例：`jpcrp_cor:`）を含めたフルネームをそのまま使用します。
- **構造化の分離**: どのタグが「設備投資」「研究開発費」や「ガバナンス」に該当するかの判定（マッピング）は、インジェクション時ではなく、蓄積後の LLM 推論フェーズに委ねます。

## 2. 抽出アルゴリズムの詳細

`EdinetParser` クラスで実装されている抽出処理は、巨大な HTML ドキュメントを効率的かつ確実に処理するため、以下のステップを踏んでいます。

### ステップ 1: ZIP 内の HTML 特定
EDINET からダウンロードした ZIP ファイル（`type=1`）内の `PublicDoc/` フォルダ以下にある HTML ファイル（`.htm`, `.html`）をすべて列挙します。フォルダ名や拡張子の大文字・小文字の差異にも対応しています。

### ステップ 2: 2段階の正規表現によるタグ捕捉
BeautifulSoup 等の DOM パースは、10MB を超える巨大な iXBRL ファイルでは再帰深度の限界（RecursionError）に達しやすいため、正規表現による高速なフラグメント抽出を行っています。

1.  **ブロック抽出 (Outer Regex)**:
    - `<ix:nonNumeric ...> ... </ix:nonNumeric>` というペアを、後方参照を用いて抽出します。
    - `re.IGNORECASE` を指定し、`<IX:NONNUMERIC>` などの表記揺れを許容します。
2.  **属性抽出 (Inner Regex)**:
    - 抜き出したタグの開始部分から `name` 属性（タグ名）を取得します。
    - 引用符の種類（`'` または `"`）や、イコール前後のスペースの有無に左右されない柔軟なパターンを使用しています。

### ステップ 3: テキスト変換とフォールバック
抽出された HTML フラグメントは、以下の優先順位で可読性の高い形式に変換されます。

1.  **Markdown 変換**: `markdownify` を使用し、見出しやリスト構造を維持したままマークダウン形式に変換します。
2.  **Text フォールバック**: マークダウン変換が複雑すぎて失敗（RecursionError 等）した場合、即座に BeautifulSoup の `get_text()` を使用して生テキストを抽出します。
3.  **Regex クリーンアップ**: 万が一パース自体が失敗した場合、正規表現で強引に HTML タグを除去し、テキスト情報だけを死守します。

## 3. なぜ CSV を使用しないのか

EDINET が提供する CSV ファイルは数値データの取得には適していますが、定性情報（文章）については以下の問題があるため、本システムでは採用していません。

- **情報欠落**: CSV では長大な文章が途中で切断されたり、表形式の構造が完全に崩壊したりするケースが多い。
- **文脈の喪失**: iXBRL（HTML）形式であれば、図表や文字飾りの情報を（マークダウンとして）ある程度保持できるため、LLM が文脈を理解しやすくなります。

## 4. 今後の展望：LLM 主導のセマンティック・マッピング

本ロジックによって蓄積された「全タグ・全テキスト」のデータに対し、別途 LLM を用いて以下の処理を行います。

- **タグの推論**: 「この企業のこの期において、設備投資や研究開発、あるいはガバナンスに関する記述が含まれるタグはどれか」を LLM に判断させます。
- **動的辞書の構築**: 推論結果をナレッジとして保持し、同じ会計基準を採用している他企業へのマッピングに再利用します。
- **非定型データの正規化**: タグ名が標準的でない（企業独自タグ）場合でも、内容に基づいて意味的に統合します。
