# J-Quants Provider 意思決定履歴 (Decision Log)

本ドキュメントは、J-Quants Providerの開発において行われた重要な技術的・設計的判断を時系列で記録するものである。

---

## 2026-05-06: データの全初期化（クリーンスタート）の実施

### 1. 背景と事象
蓄積されたDuckDB内の株価データにおいて、以下の深刻な不整合が判明した：
- **コード形式の混在**: 旧形式（4桁）と新形式（5桁）のデータが混在し、マスターデータとの結合が破壊されていた。
- **データ欠落**: APIプランの制約および同期ロジックの不備により、約2年間のデータが欠落していた。
- **孤立データ**: 保存されていたデータの99.9%が、マスターテーブルと紐付かない孤立したレコードであった。

### 2. 下された決定
既存のデータベースファイルを「修復不能な破損状態」と見なし、以下の措置を講じる：
1. **物理削除**: `master`, `prices`, `financials` の全シャードを物理的に削除。
2. **ロジック刷新**: 5桁コードへの強制標準化およびプラン制限エラー（400）の許容ロジックを実装。
3. **フルバックフィル**: 最新の正常なロジックを用いて、ゼロから全期間のデータを再取得する。

### 3. 判断の根拠
- **信頼性の確保**: 部分的なパッチ修正では将来的に「原因不明の不整合」が再発するリスクが高く、分析基盤としての信頼性を100%に保つにはリセットが最善であるため。
- **コストの比較**: 数万件の誤ったデータをクレンジングする労力よりも、正常なロジックで再同期する方が短時間かつ確実であるため。

### 4. 効果
- スキーマ、データ形式、マスターデータの紐付けが完全に正常化された。
- 今後の全データが5桁標準で蓄積されることが保証された。
